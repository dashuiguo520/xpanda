# rAthena Web 挂机系统分析存档

更新时间：2026-08-28

## 1. 项目位置与界面来源

- rAthena：`D:\Ro Server\rathena`
- rathena-web：`D:\Ro Server\rathena-web`
- 挂机功能界面图：`D:\Ro Server\rathena-web\.img\1.png` 至 `7.png`
- 服务端运行目录：`D:\Ro Server\xra`

界面包含基础、怪物、技能、拾取、恢复、瞬移、跟随七组设置。

## 2. 已确定的总体方向

采用服务端权威挂机架构：

```text
rathena-web 前端
  ↓ 配置、启停、查看状态
backendN 网关
  ↓ 专用挂机控制协议
rAthena map-server
  ↓ 执行挂机状态机并进行所有游戏规则校验
char-server + SQL
  ↓ 保存角色挂机配置
```

职责边界：

- rAthena：挂机状态机、索敌、移动、战斗、技能、恢复、瞬移、拾取、跟随、规则校验和持久化。
- backendN：保持游戏连接、转发配置和状态，不执行索敌与战斗决策。
- 网页：编辑配置、启动/暂停/停止、显示实时状态和日志。

网页不应通过高频定时器执行挂机逻辑，避免后台页面降频、刷新或关闭导致状态机失效。

## 3. rathena-web 已有能力

现有代码已经证明网页客户端与服务端协议链路可用，可作为控制和观察层复用：

- `backendN/pathfinding/mapcache.go`：读取 `map_cache.dat` 并进行单地图 A* 寻路。
- `backendN/server/entities.go`：追踪玩家、队友、怪物、NPC、传送点和地面物品。
- `backendN/server/skill.go`：构造并发送目标技能和地面技能封包。
- `backendN/server/packet_security.go`：客户端封包白名单和字段校验。
- `frontend/src/components/GameMapRadar.tsx`：已有移动、攻击、拾取和跟随操作。

这些代码后续仍可用于人工操作和状态展示，但自动决策应转移到 map-server。

## 4. rAthena 需要实现的核心模块

### 4.1 角色挂机配置

角色级配置至少包含：

- 运行模式、普通攻击、目标优先级和首领策略。
- 怪物排除、优先和躲避列表。
- 攻击、增益、辅助和治疗技能队列。
- 自动拾取、指定拾取、自动丢弃和最低保留数量。
- HP/SP 坐下阈值、恢复道具和状态恢复道具。
- 瞬移道具、瞬移技能、紧急阈值和强制间隔。
- 跟随对象、跟随攻击、辅助和治疗策略。
- 死亡处理、挂机结束动作和调试开关。

### 4.2 挂机状态机

建议基础流程：

```text
停止
→ 检查角色与地图状态
→ 紧急恢复/瞬移
→ 常规恢复与增益
→ 选择目标
→ 接近目标
→ 普通攻击或技能
→ 拾取/整理背包
→ 再次选择目标
```

需要额外处理死亡、施法、僵直、路径失败、目标消失、NPC 对话、交易、存仓、换图、队友离线和补给耗尽等状态。

### 4.3 统一调度器

- 不为每名角色建立大量独立 timer。
- 使用 map-server 统一调度器分批处理挂机角色。
- 初始决策间隔建议为 200～500ms，并允许配置安全上下限。
- 不在每次 tick 扫描整张地图，应使用现有地图区块范围查询。
- 移动、咏唱、攻击后延迟期间不重复提交动作。

### 4.4 服务端索敌

复用地图区块系统搜索附近单位，并校验：

- 怪物存活、距离和地图一致性。
- 排除、优先、躲避列表。
- MVP/MINI BOSS 策略。
- 植物类或固定伤害目标策略。
- 路径是否可达。
- 当前攻击者、最近目标和优先列表顺序。

### 4.5 移动与寻路

- 第一阶段仅做当前地图内挂机，复用 rAthena 原生碰撞与寻路。
- 暂不实现跨地图全世界寻路。
- 死亡回城后返回练级点、前往仓库后返回等需求出现时，再设计传送点拓扑。
- 动态传送点和带脚本条件的入口不能只依赖静态地图图数据。

### 4.6 攻击与技能

挂机动作不得绕过正常客户端操作的规则校验。需要复用或抽取公共校验流程：

- 技能学习等级、目标类型和作用范围。
- HP、SP、材料、弹药和装备要求。
- 距离、视线、地图限制和异常状态。
- 咏唱、攻击间隔、技能后延迟和冷却。

不得直接调用最终伤害函数，也不应通过伪造客户端封包回灌解析器完成内部执行。

### 4.7 拾取与存仓

rAthena 已有 `@autoloot`、`@alootid`、`@aloottype`，但当前配置主要保存在在线角色状态中，需要角色级持久化。

自动存仓分为两种模式：

- 正常模式：角色前往 NPC，正常打开仓库并存入物品。
- 远程模式：野外直接存仓，必须由服务器限制地图、道具 `NoStorage`、仓库容量、绑定规则、最低保留数量、频率和日志。

优先实现正常模式；远程存仓延后决定。

### 4.8 NPC 触碰事件

不能让挂机角色无条件忽略所有 `OnTouch`，否则可能绕过传送点、任务、副本机关和地图限制。

安全方案：

- warp/portal 永不忽略。
- 只允许忽略显式标记为挂机可跳过的普通 NPC 触碰事件。
- 使用 NPC 标记或 mapflag 白名单控制。
- 未标记事件维持原行为。

### 4.9 跟随

服务端直接读取队友位置，并处理：

- 换图、离线、死亡、距离过远和路径不可达。
- 跟随攻击、辅助和治疗策略。
- 治疗优先选择 HP 百分比最低且满足距离、SP、咏唱、冷却条件的队友。

### 4.10 配置持久化

完整配置字段和列表较多，不建议全部塞入 `char` 主表或角色注册变量。建议独立表：

- `autoplay_config`
- `autoplay_monster_rule`
- `autoplay_skill`
- `autoplay_loot_item`
- `autoplay_recovery_item`

char-server 负责加载和保存，map-server 在角色登录后取得配置。

### 4.11 Web 控制协议

至少需要：

- 上传并保存完整配置。
- 启动、暂停、恢复和停止。
- 返回配置版本、当前状态、当前目标、当前动作、击杀/拾取统计、错误和停止原因。

第一版可以设计专用二进制封包；正式实现前需先确定封包编号、可变长度结构、权限和版本兼容策略。

### 4.12 地图策略与安全

建议提供：

- 总开关和允许使用的账号组。
- `noautoplay` mapflag。
- PvP/GvG、副本、交易、摆摊、NPC 对话等状态下的暂停或禁止规则。
- 动作频率限制、异常停止和审计日志。
- 禁止挂机系统绕过客户端正常技能与移动限制。

## 5. 网页关闭后的会话问题

当前 backendN 的浏览器 WebSocket 断开后会关闭 char/map TCP 连接，因此角色会下线。

若要求关闭网页后继续挂机，推荐由 backendN 保留游戏 TCP 会话，并提供安全的网页重新绑定机制。第一阶段不建议实现 map-server 内的完全离线角色，因为它会影响断线清理、角色保存、换图和服务器重启恢复。

## 6. 推荐实施阶段

### 第一阶段：同地图在线挂机 MVP

- 挂机配置基础结构与启停协议。
- 统一调度器和状态机骨架。
- 当前地图索敌、移动和普通攻击。
- 攻击技能、恢复道具、瞬移和原生自动拾取。
- 死亡停止或返回存档点。
- mapflag、权限、状态回报和日志。

暂不包括跨地图寻路、远程存仓、完全离线挂机和 NPC 触碰忽略。

### 第二阶段：完整战斗与队伍

- 技能优先队列、增益和治疗。
- 怪物优先/排除/躲避列表。
- 队伍跟随、辅助和治疗。
- 自动拾取配置持久化、丢弃和背包阈值。
- 安全的 NPC 触碰白名单。

### 第三阶段：跨地图与会话保持

- 正常 NPC 自动存仓和返回。
- 跨地图传送点拓扑。
- 浏览器断开后 backendN 保持游戏会话。
- 经确认后再考虑远程存仓或完全离线角色。

## 7. 开工前仍需确认的产品决策

1. 关闭网页后是否必须继续挂机。
2. 自动存仓是正常前往 NPC，还是允许野外远程存仓。
3. 死亡后只回存档点，还是必须自动返回原练级地图。
4. 哪些地图和账号组允许挂机。
5. NPC 触碰忽略的明确范围。
6. 第一阶段是否只支持 Renewal 模式和当前 `PACKETVER 20250716`。
